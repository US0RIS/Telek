# Claude instructions for Telek

Before making substantive changes, read these files in this order:

1. `CRITERIA.md` — authoritative definition of the goal and what counts.
2. `HANDOFF.md` — current project understanding, completed work, and next priorities.
3. `docs/PHYSICS.md` — current physical assumptions and actuator candidates.
4. `docs/ARCHITECTURE.md` — software boundaries.

Do not relax the portability, unprepared-environment, unmodified-target, or real-mechanical-effect requirements merely to produce an easier demo.

The main unsolved problem is not gesture recognition. It is portable, target-selective remote momentum transfer to ordinary unmodified macroscopic objects. The current first lead is phased airborne ultrasound, but it is a hypothesis to test quantitatively, not a predetermined answer.

Prefer changes that make the project more falsifiable: explicit equations/assumptions, literature-backed measured data, simulations, tests, mechanism comparisons, or bounded experiments. Keep physical bounds, published measurements, and Telek's own results visibly separate.

At the end of a substantial turn, update `HANDOFF.md` if the best current understanding or next priorities changed.
